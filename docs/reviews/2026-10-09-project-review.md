以下 R1–R3 的问题描述和隔离复现均为修复前事实。

## R1 · P2：合并成功的系列可能立即超过读取上限

**位置：** [AssetRepository.mergeSeries](../../apps/server/src/database/assets.ts#L295)、[AssetSeriesGraph.family](../../apps/server/src/database/asset-series.ts#L61)、[批量选择](../../apps/web/src/features/workspace/gallery-selection.ts#L10)。

合并入口接受 2–1000 个素材 ID，只检查归属、存在性和类型；显式链接会连同既有编辑家族一起合并。系列详情的 1000 上限则统计全部图节点，包括素材、任务、批次及隐藏/已删除的祖先。两者不是同一个计数单位，合并也未检查结果是否仍可完整读取。

**隔离复现：** 临时 SQLite 中创建 501 个独立任务及对应图片输出，调用真实 `POST /internal/assets/series`，返回 **204**；图库分组计数为 **501**，随后 `GET /internal/assets/:id/series` 返回 **200、`truncated: true`**。无需 1000 张作品就能触发，合并已有家族也可能以更少的请求 ID 触发。

**影响：** 刚创建的系列无法完整批量选择或整系列删除，编辑器只读到部分内容。合并没有拆分入口，用户只能关闭分组后分批处理；这不是数据丢失，但会使正常整理操作进入难以恢复的状态。

**建议：** 定义合并后的可操作性契约。优先为系列成员提供有界分页并让批量操作完整读取；短期可在同一事务内检查合并后的图规模，超限拒绝并解释原因。不能仅将常量调大或忽略 `truncated`。回归应覆盖生成输出、上传素材、批次、历史删除节点及合并两个既有大系列。

## R2 · P2：整系列删除部分失败后，原确认框无法可靠重试

**位置：** [deleteTargets / deleteSeries](../../apps/web/src/features/workspace/workspace.tsx#L333)、[系列详情路由](../../apps/server/src/routes/resources.ts#L571)。

整系列删除先用封面 ID 获取家族，再并发删除素材，最后删除终态失败任务。部分素材删除失败会抛错，确认框仍保留原 `seriesDeletion`；再次点击仍用原封面获取系列。如果封面已经成功删除，详情入口会直接返回 404。所有素材删除成功、随后失败任务删除失败时也有同一问题。

**隔离复现：** 两件上传素材合并；按前端顺序调用真实路由，注入第二件素材删除失败，得到 **[204, 500]**。仍有一件存活素材，但以旧封面重新查询系列得到 **404**。复现使用真实仓储/路由和注入失败，不是浏览器点击验收；确认框保留原 ID 的结论来自源码追踪。

**影响：** 错误提示要求重试，但原确认框的操作被已删除锚点阻断。用户必须退出确认框、重新选择剩余素材或到任务列表逐项处理。

**建议：** 删除计划保存明确的待处理素材/任务 ID，成功后从计划移除，失败只重试余项；区分“已不存在”和真实失败。不要在重试时依赖已删除封面重新发现成员。若引入服务端批量接口，保留所有权验证、活动任务检查和明确的部分成功语义。回归覆盖封面先成功、任务删除后失败，以及删除成功但响应丢失。

## R3 · P2：删除确认承诺移除媒体文件，实际只做软删除

**位置：** [删除确认文案](../../apps/web/src/features/workspace/workspace.tsx#L341)、[AssetMediaService.softDelete](../../apps/server/src/media/asset-media-service.ts#L430)、[AssetRepository.softDelete](../../apps/server/src/database/assets.ts#L394)。

确认框写着“这会删除服务器上的作品及其媒体文件”，中英日翻译也表达相同含义。实现只设置 `deleted_at`、移除项目成员关系并写事件，没有移除普通素材的原文件或缩略图。临时视频帧清理是另外一条路径，不能当作普通素材的自动清理机制。

**隔离复现：** 通过真实媒体服务在临时目录写入 PNG 和缩略图，DELETE 返回 **204**；随后内容接口返回 **404**，但原图、缩略图的 `stat` 仍成功且大小大于零。

**影响：** 不会继续通过正常媒体接口暴露已删除素材，但用户可能错误地认为磁盘空间已释放、服务器上已无该文件。全量离线归档仍会包含保留的托管文件。

**建议：** 先修正三个语言的确认文案，明确“从图库删除，暂不释放存储空间”。物理清理应独立设计引用检查、活动任务保护、失败恢复和保留策略，不能为满足文案直接 `unlink`。首次审查只修正文档边界；后续 UI 文案修正见上方实施结果。
